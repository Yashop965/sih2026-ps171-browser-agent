  rule 16 + a "TASK CHECKLIST" prompt section. End-to-end optional (empty list
  degrades to old behavior). +7 tests. 296→303.

## Live test: real Wikipedia (two-search)

Task: *search "Web browser" → open it → search "Progressive web app" → open it;
COMPLETE only when the PWA article is on screen.*

- **Pre-fix:** hard-crashed at step 20 on the navigating-click EXTRACT
  (`status: failed`).
- **Post-fix (port-retry + checklist), driven via CDP against the real popup UI +
  ground-truth `browser.storage.local` log:** run reached step 46,
  `status: complete`, tab landed on `en.wikipedia.org/wiki/Progressive_web_app`.
  DONE was checklist-gated ("4/4 done"), not a bare LLM blurt.
- **Known remaining symptom (user's 3rd run):** the checklist sat at "2/4 done" for
  ~40 steps. Cause: the flaky small LLM kept dropping the `checklist` field on
  degraded steps ("Conservative fallback / Failed to parse JSON"), so the gate had
  nothing to trust and the agent cycled between the PWA article and the
  advanced-search page (`w/index.php?search=`) before a clean parse finally
  completed it. → this is exactly what **issue #100** addresses (a local vision
  stop that doesn't depend on the LLM).

## Root-cause insight (why the checklist alone wasn't enough)

The "reached the right page many times but didn't stop" symptom is a
**loop-control** problem, not a detection problem. A better detector (vision) only
helps if we hard-wire "goal confirmed → stop the loop." Hence #100 is designed as:
**cheap deterministic URL/title backstop (fast path) + optional local Florence-2
OCR/VQA confirm (proof the content actually rendered), screenshot never leaves the
device** (saves an LLM round-trip + cost + latency).

## Env cheatsheet

- Server: `python -m uvicorn server.main:app --port 8000` (real LLM key in
  `server/.env`); smoke-test `POST /plan` → check `degraded: false` **and** that
  `checklist` echoes back (the new contract).
- Chrome: `--user-data-dir=C:/Users/yashs/chrome-autonomy-test
  --load-extension=<repo>/dist/chrome-mv3 --remote-debugging-port=9222`.
  **Reload the extension after every rebuild** — the running SW keeps the old code.
  MV3 SW spins down when idle; read the ground-truth log from
  `browser.storage.local` (`sih_agent_task_state`) via any extension page, not the
  DOM.
- e2e driver: `node scripts/run_bug_c_e2e.mjs` (kick off via the real popup UI, then
  watch the persisted log; robust to the agent clobbering the popup-as-a-tab).
  `scripts/run_autonomy_live.mjs` is the older DOM-scraping variant.
- The flaky small model frequently drops the `checklist`/JSON field → "Planner
  degraded: Conservative fallback". That path is non-fatal (planner.py → conservative
  fallback, no "Test Data" typing).
