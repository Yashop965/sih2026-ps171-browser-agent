## 3. Bugs found (filed as issues, NOT yet fixed)

- **#84 (P1) — No key-press primitive.** Action vocabulary is
  CLICK/TYPE/SCROLL/SELECT/NAVIGATE/WAIT/DONE; there is no Enter. Wikipedia
  search submits on Enter (or a dropdown suggestion that isn't in the DOM
  registry), so the agent can type a query but never submit it. Proposed:
  add `KEY` action (`doKey` dispatches keydown/keypress/keyup) through
  actions.ts, planner, prompt, and popup loop.
- **#85 (P1) — 429 → destructive fallback.** The custom-endpoint LLM client
  has no retry/backoff, so a transient 429 immediately degrades the planner;
  the heuristic fallback then types synthetic values ("Test Data") into the
  first live input on the page — it overwrote the agent's own search query,
  making the stall unrecoverable. Proposed: in-client retry w/ backoff on
  429/5xx, and a conservative fallback that only fills fields the task
  actually references (use the prompt's `task_kv` extraction).

### Uncommitted production fixes in `src/entrypoints/background.ts`

Made while prepping the live test (dist rebuilt, **not yet committed/PR'd**):
1. `EXECUTE` handler: a click/submit that **navigates** the tab disconnects
   the content port → previously logged as a false failure (planner would
   retry-loop). The catch block now detects the navigation-disconnect and
   reports success ("page navigated - will re-extract the new page").
2. `resolveWebTab(sender)` helper wired into EXTRACT / EXECUTE / NAVIGATE_TAB:
   prefer `sender.tab` only when it is a real http(s) web page, else fall
   back to the active web tab, skipping `chrome-extension://` / `chrome://`
   pages. Without this, a CDP-driven popup tab made the agent target the
   extension's own page instead of the web tab.
3. Hoisted `tabId` above the EXECUTE `try` — the new nav-catch referenced it
   from catch scope (would have thrown `ReferenceError` on exactly the
   navigation path it was added for). Verified TS18004 gone.
